# Converter Plugins

This folder contains code and information for converter plugins, to allow external converters to interface with this service. This file documents the structure, as well as documents the structure of the `.json` files used for the database, since that format doesn't allow comments.

## Structure

This folder contains the following files and directories:

**Files:**

- `__init__.py` (Standard Python package file)
- `base.py` (Defines the base Python classes for converter plugins)
- `doc.md` (This file)
- `formats.json` (Source file for database information on file formats)

**Utility Folders:**

- `example` (Example implementation of a converter plugin, showing many possible features)
- `template` and `script_template` (Template plugin folders, which are used by the script `psdi-data-convert-create-plugin` to create new plugins)

**Plugin Folders:**

- `atomsk` (Atomsk)
- `c2x` (c2x)
- `openbabel` (Open Babel)
- (other converters we store information on but which aren't yet supported)

## `formats.json`

The `formats.json` file in this folder is the source file for information about file formats which is compiled into the singular database file when the `psdi-data-convert-install-plugins` script is called. The structure of this file is a singular key "formats", for a list of objects defining each format. Each object has the following keys:

- **extension** (string) - The typical extension of the file format, without the leading full-stop (e.g. "pdb", not ".pdb"). If the format has more than one associated extension, other extensions should be listed as separate objects with only the keys "extension", "id" (with a unique ID for this, not the same as the primary object), and "alias_of" (which should be the ID of the primary object)
- **note** (string) - A brief description of the format
- **id** (int) - Integer representation of a UUID for the object, as generated by e.g. `import uuid; print(uuid.uuid4().int)` in Python
- **format** (string) - The name of the format as it's referred to by the c2x converter (this key is liable to be renamed in the future for clarity)
- Property support keys (bool or `null`) - Whether or not the format supports information on a certain type of property in a retrievable way, or `null` if unknown.
  - **composition** - Chemical composition (how many of each element)
  - **two_dim** - 2D (or full 3D) representation of the positions of atoms (liable to be removed in the future as it is rare for formats to have only 2D positions)
  - **three_dim** - Full 3D representation of the positions of atoms
  - **connections** - How atoms are connected to each other
- **precision** (int or `null`) - How many base-10 digits of numerical information are stored for e.g. positional information (most formats are flexible in this and can support more digits. If in doubt, use the value output by "default", whatever feels best as the default for you)
- **alias_of** - Used only for alternate extensions of formats, alongside only the **extension** and **id** keys, the former providing the alternate extension, **id** being a new ID for this, and **alias_of** providing the ID of the primary format object which stores the remaining information about this format
